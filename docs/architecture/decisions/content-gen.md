| **Structured story text (2026-09-19)** | Generated story text names entities only through closed ICU tokens (`{lead_*}`, `{c_<slug>}`, `{c_<slug>_epithet}`, `{role_<id>}`) and fills runtime values through closed slots (`{place}`, `{supply}`, `{reward}`, `{cost}`); agreement uses ICU `select` on closed registry tags (`article`, `gender`, `number`); a closed set of semantic tags (`em`, `whisper`, `shout`, `pause`) widens [item/seed-contract.md](item/seed-contract.md) §6's markup ban to meaning-only tags, never HTML or styling. Owner rulings R8–R11, 2026-09-19. Grammar: [narrative-seed/spec-token-grammar.md](narrative-seed/spec-token-grammar.md); registry: `gk-data/packs/fusion/data/seed/narrative/_registry/tokens.v1.json`. | <!-- decisions.md:151 -->
| **Narrative names are tokens (2026-09-19)** | **Story text names entities by token, never by display string.** `gk-data/packs/fusion/data/seed/narrative/_registry/names.en.v1.json` maps each lead token to a display string with closed `article`, `gender` and `number` tags — the Garden Keeper, Hourbloom, the Rotwright (owner rulings R8–R11; the product-vision row above names the same three) — and character seeds supply named characters the same way, unioned at read time and never copied into the authored file. Renaming a lead is one row edit and changes no seed and no brief hash. Seed-side half of `npc-story-events` NS5; loader: [narrative-seed/spec-names-registry.md](narrative-seed/spec-names-registry.md). | <!-- decisions.md:152 -->
| **Generated antagonist content obeys counter-doctrine (2026-09-19)** | **No generated enemy-side character carries a line keyed to its own past encounters with the player, a recruit outcome, a level, a rank or a title**; enemy lines are keyed to the faction's relation band and to world facts only. Owner ruling R13. Enforced as registry rules in `gk-data/packs/fusion/data/seed/narrative/_registry/line-pairs.v1.json` (each rule a test) and validated by `narrative-validators`; the four allegiance rows' bands JOIN `gk-data/packs/fusion/data/seed/dungeon/_registry/disposition.v1.json`, never a copy. Rules: [narrative-seed/spec-character-vocab.md](narrative-seed/spec-character-vocab.md) §6; cross-referenced to [npc-story-events-ideal.md](npc-story-events-ideal.md) §6.12. | <!-- decisions.md:153 -->
| **No hard-coded model in seedsmith (2026-09-19)** | **Every seedsmith model call resolves its model through the one config layer** — `.env` `SEEDSMITH_LLM_MODEL` → `seedsmith.toml` → `LlmCallerConfig`'s default; no adapter, helper or CLI flag carries a model id, and provenance records the model that ran (or the closed sentinels `unrecorded` / `none`). Owner ruling R6. Enforced by `gk-forge/tools/seedsmith/tests/test_no_model_literal.py`, whose five structural shapes (S1–S5) catch the literal a string grep cannot see; the `seedsmith-no-model-literal` invariant row lands with the guard script. Rules: [narrative-seed/spec-model-config-resolve.md](narrative-seed/spec-model-config-resolve.md). | <!-- decisions.md:154 -->
| **The spine is a generated seed kind with a planned frame (2026-09-19)** | **The chapter list, each chapter's piece, its scenes, beat counts and cast are an AUTHORED frame** (`gk-data/packs/fusion/data/seed/narrative/_registry/spine-frame.v1.json`); the model writes the scenes inside it, in one work order, and never changes the frame. Owner rulings R1–R3. Generated scenes load as data through the runtime programs' loader, while the hand-authored Rift prologue keeps story-scene decision S3. Seven chapter slots (the owner's seven-piece answer, 2026-09-19), chained by `after`, with the history fragments chained the same way; a chapter row with no scenes plans no spine cell, so nothing waits on authoring them. Frame: [narrative-seed/spec-arc-shapes.md](narrative-seed/spec-arc-shapes.md) §5. | <!-- decisions.md:156 -->
| **Seedsmith authors in two modes: a delegated agent, or an API (2026-10-02)** | **The authoring step sits behind one seam with exactly two implementations — a DELEGATED sub-agent acting as the authoring LLM, or an API call.** LM Studio is not one of them: it is judged too weak for seed authoring. **In delegated mode the agent MAY hand-edit seed data, and seedsmith is what makes that safe rather than what forbids it**: the agent authors, seedsmith PLANS the work and VALIDATES the result, and `ItemSeedValidator` stays the sole authority on whether a name or a row is legal. This is the one scope in which the standing "generated seed data is never hand-edited" boundary is lifted; in API mode, and for every other generated tree, generate-and-regenerate still holds in full. **Delegated mode runs ONLY on an explicit owner request** — it has no implicit trigger and specifically NO fallback when no API endpoint is configured, because a silent fall into a mode that may edit the corpus is the exact failure this rule exists to prevent. The seam defaults to API mode. Owner ruling, 2026-10-02. Distinct from the model-ID resolution row above, which governs which model id is used and not what performs the authoring. |
