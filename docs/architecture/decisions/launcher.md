# Decisions — launcher

**Player entry point, self-contained publish, and the launcher-drawn overlay surface.**

Index: [../decisions.md](../decisions.md). Rows are listed with their original line number in `decisions.md`, so a `decisions.md:<line>` citation points at the same decision it did before the decisions.md split.

| Topic | Decision |
|---|---|
| First-session progression reveals (2026-09-08) | **One authored, server-owned sequence over the lawn-first loop:** first settled PvZ lawn victory → Souls + Crazy Dave commander-sheet reveal; player level ≥3 plus a source-validated `EmpireGeneral` spawn in a settled run → empire species XP/allocation reveal; player level ≥4 after those two checkpoints → one real Dave equipment reward. Checkpoints are per-player, monotonic, idempotent, and persisted in SQLite; UI acknowledgement never grants. A level jump does not skip queue order, and reaching a level without its required run/source evidence does not auto-complete a checkpoint. The old sunflower-bind/elemental/relic four-beat plate is legacy and must not be presented as this sequence. Capture now fails closed for missing/contradictory claims; the normal PvZ producer emits `EmpireGeneral` only from vanilla lifecycle spawn entry points. Spec: [standalone/spec-first-session-progression.md](standalone/spec-first-session-progression.md). **Server/Data settlement, source verification, GET/claim, player-owned `standard` commander assignment, deterministic item mint, commander projection, and in-stage queue are implemented.** Real deploy-play acceptance remains environment-gated. | <!-- decisions.md:12 -->
| Player entry | **FusionRpg.Launcher** (WPF). Browse game folder, optional official BepInEx/MelonLoader install, plugin install, port pick, start server+game, FusionRpg self-update. See [launcher/spec.md](../launcher/spec.md) | <!-- decisions.md:13 -->

| Game / web overlay | Player switches with a **global hotkey** (default F10) **and an on-screen button drawn by the injector** in the existing host `OnGUI` chain. All entry points converge on **one** launcher toggle method. Injector -> launcher signal is a local **named pipe** `\\.\pipe\FusionRpg.Overlay` (verbs `toggle`/`ping` only, off the Unity main thread, debounced, 2 s client read timeout, one owner per machine) - not a server relay and not synthetic keystrokes. **Pause while away**: a live board holds still while the game is not the foreground process (or the in-game view is up), so opening the control room mid-wave cannot cost a run; `OverlayPause` decides but **never writes** `Time.timeScale` — `CheatActions.TickContinuous` stays its single writer and applies the pause with priority over G-TIMEFREEZE/G-TIMESCALE, restoring the captured scale on resume (guard-pinned). Player toggle, default on. The button carries **one action** (show/hide), is **in-match chrome** (hidden outside a live board so it cannot eat a menu click), scales with display height, and is **not** a second cheats surface. View host selected by **`overlayHost`** = `launcher` (default) or `injector`; **`FUSIONRPG_OVERLAY_HOST` env wins over host config**, unknown value falls back to `launcher` (matches the `FUSIONRPG_SERVER_URL` precedence). `injector` = a separate top-level borderless Win32 window **in the game process** — not a Unity texture. Locked by the 2026-08-22 spike ([../research/2026-08-22-overlay-injector-host.md](../research/2026-08-22-overlay-injector-host.md)): WebView2 objects are **apartment-bound**, so environment/controller/CoreWebView2 are created *and* consumed on one injector-owned pumped STA thread — never the Unity thread, never the pool. View is built once in the background (~300 ms) and thereafter only shown/hidden. Ships `Microsoft.Web.WebView2.Core.dll` + native `WebView2Loader.dll` (~166 KB); **Chromium is never bundled**. Missing Evergreen runtime degrades to the launcher path, never a crash. Rendering the web UI **inside Unity as a texture** stays rejected. Spec: [../launcher/overlay-spec.md](../launcher/overlay-spec.md) | <!-- decisions.md:17 -->
