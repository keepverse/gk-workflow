Two additive changes, no existing partition touched: (1) `idNamespaces.combinations` — deliberately carries **no** `{seq:03}` sequence, since `combogen` mints ids directly from the deterministic `(aptitude, archetype)` grid cell (one pipeline, zero parallel agents), not the ~125-agent collision-avoidance pattern this whole file otherwise encodes; (2) `namingGrammar.nameKey.kindPrefixes` gains `"combination"`. Neither change reassigns a prefix, shrinks a namespace, or edits a naming pattern in place — the three things `frozen: true` actually forbids per this file's own `immutability` note — so it is the additive case that note itself allows without a re-run. **A real, previously-undiscovered validator gap, found and fixed in the same change**: `NamespaceAllocation`'s own expander (`ExpandSlotOrFlat`) hard-assumed every namespace group's `idTemplate` contains a literal `{seq:03}`; `combinations` genuinely has none, so a fourth `SequenceShape.Derived` was added (`NamespaceAllocation.cs`) — prefix-matched like `ThreeDigit`/`AffixWord`, but with no further tail grammar to check, because the tail is a deterministic generator's output, not an author's sequence to get wrong. **A second, unrelated real bug found and fixed by the same verification pass**: `combogen/authored.py`'s `write_seed_file` stamped a bare `_meta.partition` (`"strain"`/`"splice"`) instead of the established multi-file-directory convention `gems` already uses (`"gems/1"`) — the exact same shape of bug (a missing directory prefix making real content invisible to `Corpus.partitions`' occupancy lookup) independently found and fixed the same day in `base-types/footing/plant/{a,b}.json`. Also fixed in the same pass, found by the real validator and not by the module's own Python tests: `OwnershipCheck`'s `quantity`/`minTier`/`grantedTier` fields are globally forbidden as author-typed magnitudes (correctly, for a recipe/workbench balance lever) but `combination`'s `ingredients[].minTier`/`.quantity` and top-level `grantedTier` are code-derived (`emit.assemble_entry`, never model-authored) — a narrow, kind-scoped exception was added (`IsCombinationDerivedTier`/`IsCombinationIngredientQuantity`), matching the file's own existing `IsCurvePoint` precedent for exactly this shape of deliberate exception. **Verified end to end**: one real generated `strain` entry (hand-authored-answer-labeled, matching `sockets-gen`'s established precedent for this environment's lack of a live model endpoint) validated with zero errors against the real, full 215-error corpus baseline (unchanged), then removed — it was verification content, not a shippable sample.
