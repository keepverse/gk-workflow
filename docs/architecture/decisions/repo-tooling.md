| **Every generator writer pins its newline; `seedsmith-lf` gates it (2026-10-04)** | **Every writer that emits a tracked text file pins `newline="\n"`, or refuses text mode entirely.** `.gitattributes` carries `* text=auto eol=lf`, so git normalises line endings on staging: a CRLF worktree file is committed as LF, `git status` reports it clean, and a byte-comparison test against the committed blob then fails for a difference that carries no meaning. Measured on this corpus: 34 tracked files were `w/crlf` with `i/lf` and an empty `git status` on all 34, produced by two writers that were bare `path.write_text(json.dumps(...), encoding="utf-8")`; one regenerated registry wrote 889,342 bytes carrying 39,596 CRLFs against a committed blob of 849,746 bytes — the same content, the other line endings. **Both house conventions are compliant and both are accepted** — `newline="\n"`, and `write_bytes` with canonical bytes, which is immune by construction — and **`newline=""` is compliant, not deficient**, because `open()` documents `''` as no translation on write; a guard that picked one convention and rejected the other would have failed working code. The `seedsmith-lf` guard (a gating `ci` row) scans by **AST, never regex**: a raw text search for `write_text` finds 73 lines containing the token while the parser finds 67 call sites, the 6 extras being comments and docstrings, so `--reconcile` prints every line the parser does not confirm rather than assuming the gap away. Its exemptions are exact `(file, line)` keys with no glob and no prefix — editing a file invalidates its key and the guard reports `EXEMPTION-STALE`, so an exemption cannot outlive its reason and accumulate into a second, unreviewed corpus. |
| **A guard must be proven to fail on the tree it is about to fix (2026-10-04)** | **A new guard is run against the broken condition before the fix lands, and that run is recorded as the acceptance gate.** A guard reporting 0 on a broken tree is indistinguishable from a clean one, so "it passes" carries no information until it has been seen to fail. `seedsmith-lf` was run before its sweep and reported 68 findings (60 `write_text`, 8 text-handle) on a tree whose own `git status` was empty; its own first scanner reported 60 where the true figure was 68, and that gap closed only because the guard was made to go red against the real corpus before it was trusted. **The rule that follows from it: a reported figure is reproduced from disk in the session that reports it, or it is not reported.** A number carried in from a ledger, a summary or an earlier session is a claim, not a measurement, and re-deriving one is cheap beside acting on a stale one. And an agent that cannot find something it was told exists is reporting information about the tree rather than obstructing the work — that report is worth more than the number it was sent to fetch, so it is read as evidence, not as a reason to keep looking. |
