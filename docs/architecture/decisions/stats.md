| **Actor layer stack (2026-09-16)** | **An actor's numbers are composed from a STACK OF LAYERS, each a source of contributions into the one `ActorHub` fold — and a layer is never a stacking tier.** The fold is per *channel* (`DerivedStatDef.Compose`: `FlatSum`/`FlatReplace`/`SumIncreased`/`MaxPriorityFlag` over `Flat`/`Increased`/`Replace`/`Flag` ops), so "layers sum together" means every layer emits `DerivedModifier`s into the same fold — **never** that one layer multiplies another. A layer carrying its own stacking rule is a second composer wearing a new word. The layers, owner-ruled 2026-09-16: **1a base species** (the race — the species' own base stats before any progression, global, shared and **frozen**, carried by `species-passive.{speciesId}`; a differential over a shared base, the Skyrim race shape, never a separate stat block); **1b player-modified species** (~~per `(player, species)`~~ per `(save, empire, species)` since 2026-09-18 — see amendment at the end of this row; append-only, in a **new table**, written only when a real mechanism modifies it — fusion picks today — so the roll is *delayed*, not removed, and a player who never fuses has no row at all); **2a specimen progression** and **2b empire species progression**, which are **mutually exclusive per actor** — a unique specimen carries 2a only and never inherits what an empire taught its species, a general actor carries 2b only, and 2b reads **the empire that owns the species** (a lawn plant reads the player's, a lawn zombie reads **Zomboss's**, `players` id 3); **3** item equipment, **4** passive tree, **5a/5b** actor and empire title (in build under `achievement-title`; `ContainerKind.ActorTitle`/`EmpireTitle` already validated — 5b is the first genuine empire-scope layer), **6** aura/patron, **7** buff/status. **Every layer is a CONTAINER** (owner, 2026-09-16: *“container, our repo standard”*) — including progression, which today reaches the fold as allocation math: 2a becomes a per-specimen container and 2b a per-(empire, species) one, each re-projected when that specimen or species levels, with the allocation math demoted from runtime contributor to projector. No layer gets an exception, because an exception is a second way to reach the fold. **The list is a closed vocabulary — open to EXTENSION, closed to INVENTION** (owner, 2026-09-16: *"layer will be extended for more mechanism but almost close, so i dont think we need any big refactor"*). A new mechanism may become a new layer through a reviewed registry entry, exactly as `ActionTag` went 8 to 9 and the atom kinds 17 to 18; what it may not do is reach an actor’s numbers by a path of its own. A feature that changes what an actor's numbers are IS a layer, and must answer which layer, what scope, what lifetime, what carrier (container bound at deploy, or a registered `IActorStatSubsystem` — a third carrier invented per feature is the defect), and how it names itself in the GG-49 SourceId grammar. Ideal: [actor-layer-compose-ideal.md](actor-layer-compose-ideal.md). **Idea phase 2026-09-16; no module built.** **⚠️ AMENDED 2026-09-18 (species-progression + solid-enforcement `save-identity` G3, rulings R1, R3 — [spec-rulings-2026-09-18.md](spec-rulings-2026-09-18.md)):** layer **1b** was keyed per `(player, species)`; a player row doubled as an empire, which R3 retires. 1b belongs to **the empire that paid** for the pick, keyed per `(save, empire, species)` — `HumanEmpireOf(save)` for every fusion today, and Zomboss's 1b is empty because he does not fuse. `rpg_player_species_mod` is born keyed `(save_id, empire_id, species_id, instance_id, …)`; an empire asset is never keyed by the person. By the same rulings, 2b's *"a lawn zombie reads **Zomboss's**, `players` id 3"* reads Zomboss's empire of the run's save, `(SaveId, EmpireId.Zomboss)` — Zomboss stops being a player row (R3), and zombie species progress for his empire (R1). Spec: [solid-enforcement/spec-save-identity.md](solid-enforcement/spec-save-identity.md) G3; map: [species-progression-map.md](species-progression-map.md) §9. | <!-- decisions.md:54 -->
| **SOLID non-negotiable (2026-09-12)** | **SOLID is binding architecture shape, not optional style.** One SSOT per responsibility; extend by contribution to the existing gate, not parallel forks; honor Hub/Funnel/Writer contracts; prefer thin contribution APIs; depend on those abstractions. An ADR, decision, or **PO confirmation that locks a SOLID violation is still a defect** — overturn and fix; never copy as intentional design. New proposals that violate SOLID are **not allowed**. Extending a feature along a SOLID-violating seam is **not allowed** until a remediation plan for that debt is named and sequenced first (or the work waits). Grandfathered debt may remain until a named fix program lands — never a template. Not a license to refactor everything for purity. **First recorded SOLID ADR defect:** ActorHub vs `BattleStatComposer` (ActorHub sole Hot overturn, same day). Enforce: DESIGN-GATE §2.15 + §5 checklist; AGENTS.md / CLAUDE.md hard boundaries. | <!-- decisions.md:57 -->
