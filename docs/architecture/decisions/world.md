| **Deployment hierarchy SSOT (2026-09-13)** | **A deployment child inherits a parent snapshot and settles back deltas — never a live reference, never a rewritten past.** Every child (lawn Bound, delve party slot, siege combatant, expedition seat) carries three snapshotted things at deploy time: pool values (`ActorResourcePools.FromStored`, seeded through a `CarryInPools`-shaped field already declared on `BattleModels.cs:192`), status specs (declarative, applied through `StatusRuntime.Apply` at the child's first tick — never a live `StatusInstance` reference, which is keyed `entity:{ptr}` and dies with the match), and sticky flags (`Downed`/`DownedOnce`/`NerveStacks`/`Wounds`/phase — `Roster` required to deploy, `Recovering`/`ActiveBound` refuse). Settlement is exactly-once per child, idempotent on `(parentId, childId)`. **⚠️ AMENDED 2026-09-18 (empire-progression, map D5 / ideal ruling R-C1; draft P1):** a **lawn commander seat** is a deployment child: the unique creature leading a lawn run moves `Roster → ActiveBound` for that run with no board tile, no ptr and no kill credit, and settles exactly once through the lawn run-end path, idempotent on `(run, instanceId)`. Its parent is home or a legion stationed in a sector; no child leaves from a legion on a lane. A specimen is in exactly one place, so a seated commander is never also a lawn Bound, a delve slot or a siege combatant for that run. Map: [empire-progression-map.md](empire-progression-map.md) D5. A dead unique/commander's assigned **rolled** gear — and, on any delve wipe, the whole party's carry-in gear and unbanked haul too — **moves**, never copies, into a per-place `rpg_corpse_cache` row instead of `item/ssot-inventory.md:452`'s prior "gear is never lost on death" rule, which is **overturned for the real-death / delve-wipe case only** (voluntary retire/fusion still releases to the armoury). Recovery clocks are per-deployment-kind (delve-counted `Recovering`, world-turn legion rest under supply, or a priced ritual) — never wall-clock, never a single unified clock. Troop stacks (species-shaped, `WorldEntityMember`) are exempt from all of the above: HoMM3 top-unit count arithmetic only, no per-unit wounds, no inventory. | **Scoped inventory hierarchy SSOT (2026-09-13)** | **`rpg_item`/`rpg_item_stock` stay the one ownership root for every inventory scope — a scope is a reachability + capacity overlay, never a second ownership table.** Empire scope (`player_id`, uncapped, `RpgStore.Items.cs:85-107`), unique-actor scope (`rpg_item_assignment`, capacity = the closed 15-role enum), delve-party scope (`loot-pack`'s `PackGrid`, footprint-derived slots), legion scope (a new slot+weight cargo overlay on `WorldEntity`, capacity aggregated from a flat tunable per-unit default until a real per-species stat exists), and sector scope (a new slot-bound `StructureKind`, capacity summing additively across active storage structures, mirroring the existing loam `CapacityBonus` discipline) are five expressions of the same pattern, not five ownership models. Every scope-to-scope move (legion↔legion, legion↔sector, a captured sector's stock to its new owner, a destroyed legion's cargo into a corpse-cache-shaped revisit-lootable place) is a single-transaction move, never a copy — the same discipline `corpse-cache` already proved for unique-specimen death. Cross-faction item transfer is **not yet buildable**: no faction other than the world's single `player_id` owns an item store today (`rpg_world_factions` has no `player_id` column, `RpgStore.World.cs:37-44`); ownership keys on the generic `FactionId`/`player_id` model (never the closed `CommanderId` enum) so a future multi-empire program is not blocked, but same-empire scopes are all this program ships. Ideal: [scoped-inventory-hierarchy-ideal.md](scoped-inventory-hierarchy-ideal.md); map: [scoped-inventory-hierarchy-map.md](scoped-inventory-hierarchy-map.md). **Idea phase locked 2026-09-13; capability map approved 2026-09-13; no module built yet.** | <!-- decisions.md:49 -->
| **Loam relics and wonders SSOT (2026-09-13)** | **Wonders are a special structure tier, funded by relics (rolled unique items) plus the existing `RubbleStock`/`IronworkStock` basic-material cost, granting a loam-generation-rate boost through a closed vocabulary sized to grow without a schema rewrite.** This wave ships **`Sector`** and **`Empire`** scope only — `World` (needs `LoamProduction.For` looped over every faction, plus the already-decided mitigation that Zomboss can contest a World-scope Wonder) and `Multiverse` (needs a player-scoped ledger that spans worlds — *amended 2026-09-19:* worlds now persist (World lifecycle row), so the blocker is a cross-world ledger, not worlds that end) are named, reserved, and deferred to their own future map, never built here. `Rarity` (`Common`/`Unique`) is a per-scope existence cap, sourced from a tunable count — never hard-coded to `1`. The effect vocabulary (`WonderEffectKind`/`WonderEffectScope`/`WonderEffectDef`) ships exactly one member, `LoamGenerationRate`, with `DefensePower`/`AuraGrant`/`EmpireBuff` named-but-unregistered for later waves. Multiple simultaneous `Empire`-scope Wonders on one faction combine by **SUM**, matching `LoamProduction`'s existing additive discipline for structure yields (adopted as the working design, reviewable at build time — a structural constant, not a tunable number). Relics mint as rolled items through the existing item-gen pipeline, across delve/expedition/world-map-assault/quest simultaneously — never a parallel drop system. The Wonder *build flow* (spending a relic at a sector) is a **hard external block on `scoped-inventory-hierarchy`** (spec'd, unbuilt): the verb's spec is written this wave so the recipe shape is ready the moment that program ships, but it cannot run end-to-end before then. Two module-level calls are deliberately **not** locked here, left to each module's own evidence-based spec: whether `wonder-structure` needs a 7th `StructureKind` value or an orthogonal tag, and the exact relic drop table/row/rate. Also **not yet locked**: a schema relaxation on the item program's `unique` `KindSpec` (or a sibling relic kind) for a never-equipped rolled item — this program files the first formal ask against the item program. | Repository topology — Keepverse split (2026-09-19) | **Locked (owner-approved plan, gate G1).** The monorepo splits into the Keepverse workspace: root `gk-workflow` (workflow, docs, agent config, `tasks/`, the `kvsplit` tool, cross-repo scripts) plus six independent sub-repos — `gk-core` (Contracts, Core, Data, CheatCore, Server, web, `gk-core/data/tuning`), `gk-forge` (generator code only), `gk-data` (**private, always**: all of `gk-data/packs/fusion/data/seed/**` + `gk-data/packs/fusion/data/generated/**` as content packs `fusion` and `keepverse`), `gk-assets` (original art), `gk-fusion` (injector hosts, Launcher, game profiles, live tools, release). **Direction contract:** gk-forge/gk-fusion compile against gk-core; gk-core reads gk-data only at runtime through `GkDataRoot` + a pack name, never references gk-fusion, and its own tests never need gk-data. A tool lives where its output's owner lives. Workspace manifest + lock, not submodules; sibling paths, not packages. Original-IP repos start from a fresh snapshot; public history is an orphan snapshot of an ip-censor-clean tree. **Execution rule:** the migration is the output of the deterministic Python tool `kvsplit`; agents only reconcile its residue by changing its rules/transforms or by normal source commits — never by editing output. Migration (`apply`) starts only on the owner's explicit command (gate GM). | **World lifecycle — world-continuity (2026-09-19)** | **Worlds never end.** `rpg_worlds.state` is the attention axis (`active \| hibernating \| idle`) and a new `outcome` column is the result axis (`contested \| won \| fallen`); exactly one `active` map world per save, enforced by a partial unique index. Taking the dominant enemy empire's seat makes the world `won` (developing) and it keeps running. The player may **advance** at any time, carrying legions and cargo up to a carry limit (larger after a win; loam never crosses). Old worlds **hibernate** on the world-turn clock (lazy coarse step) or go **idle** on the expedition clock once a warden is stationed; **wardens are resumed** as a commander and legion defending an old world, costing upkeep, never freezing decay. Losing the active world's seat makes it `fallen` and the save continues. Map: [world-continuity-map.md](world-continuity-map.md); ideal: [world-continuity-ideal.md](world-continuity-ideal.md) §6, §9 W1–W8. | <!-- decisions.md:145 -->
