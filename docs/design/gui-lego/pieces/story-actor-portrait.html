story-actor-portrait

One actor in a slot array, carrying speaking | inactive state. The speaker is distinguishable without color alone — Dialogic's portrait subsystem does exactly this, updating the portrait on a speaker change and applying highlight/unhighlight so the active speaker reads structurally. Spec: docs/architecture/story-scene/spec-actor-portrait.md.

Two actors, Penny speaking

Dave · inactive — smaller, settled, still readable

Speaking is size + lift + ring weight + opacity, never color alone: scale(1) vs scale(.94), a 4px lift, a 3px ring vs 1px, full vs 55% opacity. The inactive actor stays visible and identifiable.

Structure and rules

.story-actor-portrait            root; carries pack css, data-speaking
  .story-actor-portrait__lift    speaking posture (size + lift + ring)
  .story-actor-portrait__settle  inactive posture (smaller, dimmer)
  .story-actor-portrait__body    -> actor-sprite slot
  • The fold owns which actor speaks and which variant each carries; the piece renders what it is given and never resets a variant on a speaker change (Ren'Py's failure mode is re-showing an image by tag and silently dropping its attributes).
  • Actors are decoration for focus purposes — no tabIndex, no button or link role. The dialogue window is the focus target.
  • spriteUrl: null falls through to the sprite's honest labelled shape.

Sample payload

{
  "piece": "actor-portrait",
  "instanceId": "scene:actor:dave",
  "phase": "ready",
  "actorId": "dave",
  "speaking": true,
  "variantId": "default",
  "spriteUrl": null,
  "themeRef": { "kind": "actor", "id": "dave" },
  "slots": { "body": { "piece": "actor-sprite",
    "instanceId": "scene:actor:dave:sprite" } }
}
