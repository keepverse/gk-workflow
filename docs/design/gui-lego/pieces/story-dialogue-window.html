story-dialogue-window

The say window: the speaker's line, an optional teaching sentence, and the narration variant. It owns readability, not colour — the name tag inside it owns the speaker's identity paint. Spec: docs/architecture/story-scene/spec-dialogue-window.md.

Ren'Py separates these the same way: its say screen is a window containing the who text and the line, and the speaker region has its own id because the namebox is a separate, optional thing. So a narration beat is the same window with the name-tag slot empty — never a second component and never a fake speaker.

Spoken beat, with a teaching line

Penny

Temporal signal unstable.

The fracture is new, and something inside it is changing.

Only the line is the live region. Wrapping the whole window would re-announce the name tag and the teaching sentence on every beat.

Narration — same window, no name tag

UNSTABLE SECTOR. QUARANTINE PENDING.

Containment can save a world — or cut it away.

The narration card is structurally identical minus the tag. There is no "Narrator" label and no separate narration component.

Spoken beat, no teaching line

Dave

Uh-oh. That lawn is doing the wrong kind of wobbly.

The teaching line is omitted entirely when absent — it is never an empty paragraph.

The text-wall case, shown as a defect

A long line wraps and the window grows to a bounded height. It never paginates, scrolls or truncates — and the payload cannot even express a paragraph array, because a text wall is a script defect the beat cap catches, not a window feature.

Reviewers name the failure this prevents: "repeated deeply uninteresting cryptic exposition dumps for over twenty minutes".

Structure and rules

.story-dialogue-window
  .story-dialogue-window__nameTag    -> name-tag slot (absent on narration)
  .story-dialogue-window__line       the line; aria-live="polite" lives HERE only
  .story-dialogue-window__teaching   visually subordinate; absent when unset
  • One beat = one line + at most one teaching sentence. No pagination, no history, no scroll.
  • A line is never truncated — truncation is a defect, not a design choice.
  • Text is selectable and zoom-safe.
  • The slot is filled by the fold; the window renders whatever it is given.
