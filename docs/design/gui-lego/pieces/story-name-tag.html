story-name-tag

The current speaker's label, painted by the actor's pack — replacing a hard-coded text-ok utility class, which is the same defect as a hard-coded hex. Absent entirely on a narration beat. Spec: docs/architecture/story-scene/spec-name-tag.md.

Narration — nothing rendered

(no name-tag node at all)

A narration beat renders no tag — not an empty one, not a placeholder, not a "Narrator" label. Ren'Py's say screen behaves the same way: the who text appears only when a character spoke.

Structure and rules

.story-name-tag                 root; carries pack css custom properties
  .story-name-tag__label        the display name
  • Paint comes from themeResolved.paint; no text-ok, no identity utility class, no hex.
  • Uppercase and tracking are the pack's css, not a hard-coded utility, so a later scene can restyle the tag without touching the piece.
  • An empty displayName renders nothing — an upstream mistake cannot ship an empty tag.
  • The fold omits the payload entirely on a narration beat; the piece also guards, so absence holds even if that is missed.

The wash is color-mix(in srgb, var(--piece-accent) 12%, transparent) over the scene bed — the shipped chip convention. It needs no new pack surface, because themeStyle spreads a pack's css block only and never paint, so paint.onAccent never reaches the DOM as a variable.
