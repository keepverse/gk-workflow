story-scene-progress

Where the player is in the scene — beat n of m, as pips plus an accessible label. Spec: docs/architecture/story-scene/spec-scene-progress.md.

Two rules shape it. The label is authored by the fold and rendered verbatim, so there is one place to translate and one place to test. And a one-beat scene shows no chrome at all — that is what lets a reveal reuse this piece without a meaningless "1 of 1".

A reveal is a one-beat scene, so this piece renders no DOM node when total <= 1. There is no "1 of 1" state to design around.

Structure and rules

.story-scene-progress
  .story-scene-progress__pips     one pip per beat; current pip emphasized
  .story-scene-progress__label    accessible text
  • total is the script's own length — never a hard-coded constant, and never asserted as a literal in a test.
  • total <= 1 renders nothing, so a reveal reuses this piece cleanly.
  • Nothing is persisted: beat position is session UI state, and a tab closed before acknowledgement restarts at beat 1.
  • The current pip is distinguishable without colour alone (elongation), and the pips are aria-hidden.

Sample payload

{
  "piece": "scene-progress",
  "instanceId": "scene:progress",
  "phase": "ready",
  "index": 1,
  "total": 4,
  "label": "Beat 2 of 4",
  "showPips": true
}

index is 0-based. showPips defaults to true; a later surface may show the label alone.
