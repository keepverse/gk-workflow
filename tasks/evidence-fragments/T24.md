Notes
- The wear is decided in ONE place (`ItemWorkbench.CraftWearFor`) and carried on `WorkbenchMutation.DurabilityCurrent`, applied by `SetDurabilityCurrentUnlocked` inside the same transaction as the op — so T43 suppresses it by making that one call return null, with no second decay path.
- ⭐ **The host wire is in.** `Program.cs` supplies `CraftWearSource` from `BaseTypeSocketMaxCorpus.LoadClassById` (the same base-type seed JSON `socketMax` reads) + `DurabilityTable.DeriveMax` + the instance's ladder rung + `DeploymentHierarchyTuningHub.Tuning.CraftWearPerAttemptMilli` — the craft-wear key that already ships, so no tuning publish. A real enhance past exhaustion therefore decays, proved at the endpoint; an unknown base type or an unconfigured Hub derives no max and leaves the pair alone rather than inventing a number.
- The earlier revision of this fragment said "one wire remains" — that gap is what this commit closes.
