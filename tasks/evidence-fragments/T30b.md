## The mechanism

**Schema (`RpgStore.Loot.cs`).** `trophy_scope TEXT` / `trophy_slot INTEGER` added to
`CREATE TABLE IF NOT EXISTS drop_table_entry` (fresh DBs) plus two `EnsureColumn` calls (existing
DBs — the same idempotent-additive shape T26's `promoted_from_ordinal` already uses). Both NULL on
every pre-existing row; `ImportLootCorpus`/`LoadLootCorpus` round-trip them positionally on
`DropTableEntryRow`'s two new trailing optional fields.

**Model (`DropTableModel.cs`).** `DropTableEntryRow` gains `TrophyScope`/`TrophySlot`, both optional
so every existing construction (all 900+ real entries, every test) is unchanged.

**Validator (`DropTableValidator.cs`).** A new block ahead of the existing `ref`-based checks:
both-or-neither (`trophy-scope-slot-mismatch`), mutual exclusion with `ref_id`
(`trophy-and-ref-conflict` — SOLID L, never an overloaded `ref_id` grammar), `Material`-kind-only
(`trophy-requires-material-kind`), closed scope `{species,family}` (`trophy-scope-unknown` — R9's
`general` is explicitly refused, not accepted at lower priority), positive slot
(`trophy-slot-invalid`), and registry-bounded slot via the new `DropContentLookups.TrophySlotExists`
delegate (`trophy-slot-unknown`). The pre-existing `NeedsRef`/`MaterialExists` checks are guarded to
skip a trophy-scoped entry (its `ref_id` is legitimately empty). All six new rule ids are namespaced
`drop.*` — no new member of the closed 33+1-code list.

**The slot bound, without a count this file never reads (`MaterialCatalog.cs`).**
`IsTrophySlotIssuable(scope, slot)` answers "does ANY scopeKey in the injected registry carry this
(scope, slot) pair" — computed once, alongside the existing trophy-id set, inside
`ConfigureTrophyRegistry`. This answers "is slot inside `1..perSpecies`/`1..perFamily`" without Core
(or this validator) ever reading those two generation-time-only numbers directly, since a
parametric entry names no `scopeKey` yet (the killed species/family is only known at draw time,
T34c). Wired in `Program.cs`'s existing `DropContentLookups` construction.

**Authored shape (`droptablegen/emit.py`).** `_trophy_row(scope, slot, drop_band)`, a sibling to
`_material_row`/`_relic_row`: code decides `scope`+`slot` (never a model-facing field, confirmed by
a test asserting `audit_schema` stays clean and neither name appears in the rendered schema), the
model answers only `dropBand`, exactly the division every row-kind function in this module already
uses. NOT wired into `assemble_entry`'s own multi-group table assembly — that is real trophy
**content** authoring, and both the spec and this task's own description reserve it for T34c
("No trophy content here — T34c authors it").

**Runtime read path (`LootCorpus.cs`) — found while tracing the full round trip.** `LootCorpusReader
.ReadEntry` (the parser for `data/seed/loot/tables*.json`, the file `Program.cs` actually boots
from — a DIFFERENT corpus from `droptablegen`'s own seedsmith-authored `gk-data/packs/fusion/data/seed/items/drop-tables/`
input, per this file's own header note) did not read `trophyScope`/`trophySlot` at all. Without this
fix a trophy directive authored in the final runtime file would have silently vanished even though
the DB schema, C# model and validator all supported it — closed in the same commit since "the
persisted shape" means end-to-end, not schema-only.
