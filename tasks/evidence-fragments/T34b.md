## The mechanism

`MaterialCatalog.cs` — a host-injected trophy registry (`ConfigureTrophyRegistry`/`IsTrophyId`,
re-assignable like every other tuning hub, never throw-on-second-call), the scope-token grammar
(`TryParseTrophyScopeToken`/`ComposeTrophyId`: `trophy.species.{slot}` / `trophy.family.{slot}`, ONE
dot fewer than a concrete id — a recipe never authors a literal per-species id in 904 recipes), and
`ParseTrophyRegistryIds` (the JSON reader for T34's own generated `trophy-registry.json`). `ClassOf`
now resolves a trophy id via either shape: a scope token structurally (no registry lookup — it names
no scopeKey yet) or a concrete id via registry membership.

`MaterialTuning.cs` — `MaterialOperationCost` gained an optional `Trophy` leg (parsed by the SAME
generic `Leg()` helper every other optional class already uses; `null` today, no real row exists —
T34d publishes one). `SpeciesMultiplierMilli`'s threshold check is extracted into
`IsAboveSpeciesThreshold`, reused by `Resolve()` to gate the trophy leg itself (binary — present or
absent — never priced at a neutral quantity the way the OTHER legs are for a species-less/below-
threshold target).

`MaterialRecipeCatalog.cs` — `RecipeContext` gains `BoundSpeciesId`/`BoundSpeciesFamilies`/
`TrophyStock` (all target properties, D26-compliant, all optional/defaulted so every existing call
site is unchanged — proven by the mechanically-enforced `No_cost_input_reads_a_player_property`
test, updated to list the three new names). `Load()`'s cost-line loop lets a scope token bypass the
closed-27 `IsIssuable` gate (it was never meant to be a concrete id) while still running through
`CostClassMatrix.Check`. `Resolve()` is the ONE site (Strengthen pass item 3) that turns a scope
token into the concrete id a spend debits — species scope composes+verifies against
`BoundSpeciesId`; family scope (R22) walks `BoundSpeciesFamilies` in its own family-map.json order
and picks the first whose `TrophyStock` covers the whole leg, never splitting one line across two
families; either shape refuses by name (naming every acceptable id for family scope) rather than
dropping the leg.

`Program.cs`/`ContractTuningTestBootstrap.cs` — both inject the SAME real, committed
`trophy-registry.json` (production reads the file; the test bootstrap reads it too, matching the
existing `ActionBaseTuningHub`/`CommanderDirectoryHub` precedent) — no synthetic registry override
anywhere, so every test naming a real id (`trophy.species.abyssswordstar.1`) resolves exactly as
production would.
