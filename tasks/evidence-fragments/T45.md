## Two independent rules, one existing code

`DropTableValidator.ValidateGroup` (entry-level, near the existing `AffixChannels.IsKnown` check)
refuses an `assurance.*` material entry whose OWN `AffixChannel` is not `boss`, wherever it is
authored — root table or nested. `ValidateAssuranceBossOnly` (new, wired into `Validate` right before
`ValidateStandaloneContainment`) closes the loophole the entry-level check alone cannot: a leaf entry
correctly authored `boss`-channel, but reached through a `drop`-channel `Table` link one or more levels
up. Both raise the SAME `drop.assurance-non-boss` code under the existing `ContentRuleViolated{drop.*}`
namespace — no new `AtomRejectionReason` member, matching `No_new_member_of_the_closed_thirty_three_code_list`'s
own closed-count assertion (still 35, unchanged, re-run as part of the `~Drop` filter above).

`ValidateAssuranceBossOnly` is a memoized depth-first "does this table's reachable subgraph carry an
assurance entry" walk, checked against every `Table`-kind entry in the corpus (not scoped to
source-reachable tables, matching `ValidateNesting`'s own precedent of walking every table as its own
root). It is safe against cycles by construction: by the time it runs, every table in `tables` has
already passed `ValidateNesting` as its own root (earlier in `Validate`'s pipeline), so the whole graph
is proven acyclic and the memoized walk terminates without a separate `onPath` guard.
