## Why this was in this lane's fence, and why it mattered

`gk-forge/tools/seedsmith/**` is inside lane `sgc-2`'s `--allow`, and the defect was found by this lane's own
verification: S4's full-suite comparison showed `test_themes_v2::test_publish_is_idempotent` as the one
NEW failure, and the lane's first baseline run had left the committed registry CRLF-dirtied. Root cause
read directly: three text-mode writers without `newline="\n"`, reached by
`gk-forge/tools/seedsmith/tests/test_themes_v2.py`'s idempotence test, which called `publish_v2(write=True)`
against the **production** registry. The line endings made the assertion pass or fail depending on
whether an earlier test in the same run had already dirtied the file — a fresh LF checkout failed, a
polluted one passed.

  `write_text`/`fdopen` on a tracked corpus file is a separate, larger row and is not claimed here.
