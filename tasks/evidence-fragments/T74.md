**What the authored test fixture had to get right (recorded so it is not re-derived).** The host's store
ships no actions, so the fixture authors one; its container must hold a real seeded atom or
`ActionContainerEffectResolverFactory.Build` cannot resolve it and `BattleRunState.BindContainers`
throws. The trap is `ActionRow`'s default `MaxRange = 0`: a web match resolves on a real
`NormalBattleBoard`, so an action left at that default is refused by the engine's own range gate every
round and is never declared at all — which looks exactly like a pricing fault and is not one. `MinRange 0
/ MaxRange int.MaxValue / RequiresLineOfSight false`, matching the engine's own basic-attack row, is what
makes the fixture measure the price.
