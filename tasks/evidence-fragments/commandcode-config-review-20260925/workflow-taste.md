# Workflow Taste
- Prefers reliable, reusable Python automation for repository housekeeping instead of one-off manual cleanup. Confidence: 0.9
- Prefers conservative, explicitly staged cleanup: before proposing any cleanup, read the most recent handoff to establish the current situation; reconcile any small eligible subset against the full inventory and explicitly account for the rest with blocker categories; before any mutation, provide a read-only dry-run audit with scope, state counts, and blockers; separate discovery/marking from removal; treat work as complete only when merged or pushed with no outstanding work; and require agent/human confirmation before treating dirty or test-looking files as disposable. Confidence: 0.95
- For cleanup workflows, prefers moving recoverable artifacts to the operating system's Recycle Bin instead of permanently deleting them. Confidence: 0.95
- In worktree-cleanup audits, wants ignored output classified by provenance rather than treating all ignored files as unfinished: ordinary .NET/React build and cache residue should be distinguished from source changes and preservation-sensitive SeedSmith/generated deliverables or evidence, which require review. Confidence: 0.9
- For large cleanup inventories, wants extra independent agent audits to supplement conservative automated classification, because a fail-closed tool may report only a small eligible subset and miss the broader worktree population. When an answer covers only the tool's automatic candidates, the user pushes back with terse challenges ("no, what about 100+ worktree?") and expects the FULL population inventory with a total count, partitioned into immediate, strong-but-blocked (e.g. detached), conditional, false-positive, and must-retain groups, plus an explicit acknowledgment when the earlier answer was incomplete. Confidence: 0.9
