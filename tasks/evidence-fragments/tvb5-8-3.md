# TVB5.8.3 — increment 4/68: `FusionRpg.Core.Atoms.Tests` (and the blocker that held it)

The increment was blocked twice before it could be planned, and both blockers were real:

1. **A cross-folder helper.** `Atoms/EffectSeedFixtureOracle.cs` is used by five files outside `Atoms/`
   (`EffectBagAuditTests.cs`, `EffectBagTests.cs`, `EffectFunnelTests.cs`,
   `Combat/EffectBagMergedElementPayloadTests.cs`, `Combat/OwnerElementFallbackTests.cs`). Moving it with the
   project left the residual with `CS0103: The name 'EffectSeedCatalog' does not exist` — the gate reverted,
   correctly.
2. **A cross-folder `[ModuleInitializer]`.** `World/StructureCatalogTestBootstrap.cs` configures
   `StructureCatalog`; the Atoms tests read it (`AtomKindRegistry.StructureIds()`), so the new project's own
   run failed with `StructureCatalog.Configure was never called` — the gate reverted again, correctly.

Both are the same class the analyzer's per-folder SCC model does not see, and both are fixable with fields
the spec already has: the project's `include` becomes the explicit file list (74 files) and the two shared
inputs are added to its `links`, so each stays in the residual and is compiled into both assemblies — the
same pattern `DataTestStore.cs` and the shared `.props` already use. No new manifest field, no tool change.
