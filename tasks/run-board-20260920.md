### 2026-09-23 06:05 — RULING: RS-CF2 and ADG-F5 are one root cause, two lanes; reconcile to ONE predicate

**The root cause, captured (lane `rscf2`, `tasks/reports/rs-cf2.md`):**

```

   at FusionRpg.Data.RpgStore.<>c__DisplayClass1293_0.<TryRollActionUnlocks>b__4(...) RpgStore.UniqueActors.cs:2148
```

The roll drew from `ActionEligibility.Candidates(...)` minus `state.Held`. **Eligibility answers "who may hold this
action" (general / family / species) — never "may this be granted"** — so the pool carried `act.attack`
(`kind = basic`), which `ValidateGrant` refuses by construction (`BasicCollision`); the grant delegate then threw
*inside the XP award's own transaction*. It was intermittent because **two seeded coin flips** gate it: the draw is
seeded off a fresh `Guid` instance id per specimen, and `TryAccept` accepts 50% at `earnCount = 0`.

**What each lane landed:**

| Lane | Predicate added | Also delivered |
|---|---|---|
| `rscf2` (RS-CF2) | `ActionValidator.ValidateGrantable(action)` — the row-level half of `ValidateGrant` | the roll's chooser reads it **and** `RpgStore.TryRollActionUnlocks` filters on it; `UniqueActorXpUnlockRollTests` (148 lines) |
| `adg-f5` (ADG-F5) | `ActionValidator.GrantRefusal(action)` — the same two ACTION-only refusals, extracted | the *outcome* semantics: a refused option is **skipped and recorded** (`UnlockSkip` on `UnlockGrantOutcome.Skipped`), never thrown |

**Ruling:** one canonical predicate, both behaviours kept.

1. The names must collapse to **one** — two names for one rule is exactly the drift both lanes set out to prevent,
   and `rscf2`'s comment says so in as many words. I keep `ValidateGrantable` (it is the name the chooser, the SQL
   filter and the test file already use) and retire `GrantRefusal` to it.
2. **`rscf2`'s reach is the root fix**: the chooser *and* the query stop offering an un-grantable row, so the throw
   never happens.
3. **`adg-f5`'s behaviour is the contract**: if an un-grantable row ever reaches the write path again, it is skipped
   and recorded with the validator's own reason — a roll must never throw, whatever the pool holds. Defence in depth,
   not duplication: one predicate, two call sites with different jobs.
4. Both lanes' tests land. Both rows tick with a pointer to the other.

**Lesson for dispatch**: RS-CF2 (an intermittent 500) and ADG-F5 (a roll that throws instead of skipping) were the
same seam, dispatched as two lanes because the symptoms differed. When a finding is "X throws", the manager should
ask *what else reads the same predicate* before spawning a second lane at the same root.
